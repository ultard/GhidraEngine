# Как это работает

Библиотека отвечает на два разных вопроса: «это тот же самый файл?» и «это та же самая
картинка?». Первый решается хешами содержимого, второй — перцептивными подписями.
Каждая стадия отсеивает кандидатов до того, как следующая потратит на них I/O или CPU.

```
обход ФС → кеш → размер → частичный хеш → полный хеш       точные дубликаты
              ↘ декод 1/8 → pHash/dHash/цвет → MIH → кластеры   похожие
```

## 1. Обход файловой системы

`src/core/enumerate.cpp` рекурсивно обходит корни, отбрасывая по дешёвым признакам:
размер вне `min_file_size`/`max_file_size`, скрытые файлы (`skip_hidden`), глоб-паттерны
`exclude_patterns`, глубина `max_depth`, расширение (если не включён `probe_unknown_extensions`).

Каждый файл идентифицируется не путём, а физической идентичностью: том + file id на
Windows, `st_dev` + `st_ino` на POSIX. Из этого следует два свойства:

- жёсткие ссылки на один экстент схлопываются в одну запись, а не выдаются как дубликаты
  (счётчик `stats.hardlinks_collapsed`);
- обход не зацикливается на симлинках-петлях даже при `follow_symlinks = true`.

## 2. Классификация

Тип медиа определяется по первым байтам файла, а не по расширению. Расширение решает лишь,
стоит ли вообще открывать файл; с `probe_unknown_extensions` открывается всё, и JPEG с
именем `.bak` будет найден.

## 3. Точные дубликаты

Каскад построен так, чтобы полностью читать файл как можно реже:

1. **Уникальный размер** — мгновенный отсев, файл даже не открывается второй раз.
2. **Частичный хеш** — XXH3-128 по первым и последним 64 KiB. Для файлов ≤ 128 KiB он
   покрывает содержимое целиком и сразу считается полным.
3. **Полный хеш** — потоковый XXH3-128, только для групп, выживших после частичного.

`verify_bytes` добавляет побайтовое сравнение поверх этого. По умолчанию выключено:
коллизия 128-битного хеша практически невозможна, а лишний проход стоит второго чтения.

Изображение читается целиком только тогда, когда его всё равно собираются декодировать.
При `detect_similar = false` оно идёт по тому же дешёвому каскаду, что и видео.

## 4. Подпись изображения

JPEG декодируется libjpeg-turbo прямо из DCT-коэффициентов в масштабе 1/8
(6000×4000 → 750×500) — полноразмерный битмап не создаётся никогда. Остальные форматы
(PNG, WebP, AVIF, HEIF, TIFF, BMP, GIF, raw) идут через FFmpeg. Результат в обоих случаях —
один буфер 32×32 в градациях серого плюс хроматика.

Из этого буфера считаются четыре величины. Декодирование доминирует по стоимости, поэтому
дополнительные хеши почти бесплатны, а каждый закрывает слабое место остальных:

| Величина | Что это | Что ловит |
|---|---|---|
| `phash64` | DCT 32×32, левый верхний угол 8×8 без DC, порог по медиане | пережатие, ресайз, лёгкую коррекцию |
| `phash256` | тот же DCT, угол 16×16 | ложные срабатывания на больших корпусах |
| `dhash64` | горизонтальный градиент | сдвиги яркости, к которым DCT равнодушен |
| `color` | средние по сетке 4×4 в двух каналах цветности | разные снимки, совпадающие в градациях серого |

Пара считается похожей, только если проходит **все** настроенные пороги
(`phash_threshold`, `phash256_threshold`, `dhash_threshold`, `color_threshold`).

`dihedral_invariant` приводит миниатюру к канонической ориентации до хеширования, так что
все 8 поворотов и отражений дают одну подпись. Изображения меньше `min_dimension` по любой
стороне пропускаются: сигнала в них слишком мало.

## 5. Подпись видео

`AVDISCARD_NONKEY` — декодируются только ключевые кадры. Берётся `frame_samples` отсчётов
равномерно по таймлайну, первые и последние `edge_skip_fraction` пропускаются (заставки и
титры). Кадры с дисперсией ниже `min_frame_variance` (чёрные, затемнения) хешируются во
что-то, что похоже на всё подряд, — они пересемплируются рядом.

Сравнение: сначала дешёвый префильтр по длительности (`duration_tolerance`), затем доля
кадров, совпавших в пределах `frame_threshold` бит, против `min_frame_match_ratio`.
Кадры хранятся и в порядке таймлайна, и отсортированными — второе даёт сравнение,
независимое от смещения. `subclip_detection` находит ролик внутри более длинного, но
квадратичен по числу отсчётов на пару кандидатов и потому выключен.

## 6. Поиск похожих: Multi-Index Hashing

64-битный код режется на 4 полосы по 16 бит. Пара на расстоянии Хэмминга ≤ d обязана
совпадать хотя бы в одной полосе с точностью до `floor(d/4)` — иначе суммарное расстояние
превысило бы d. Поэтому достаточно опросить каждую полосу в малом радиусе и проверить
только полученных кандидатов.

Индекс **точный**, а не приближённый: тест сверяет его выдачу с полным перебором. Когда
радиус проб по полосе превысил бы 4, индекс сам переключается на линейный скан — на таких
порогах перебор дешевле, а урезанный набор проб молча терял бы пары.

## 7. Кластеризация и выбор keeper

- `Strict` (по умолчанию) — файл попадает в кластер, только если совпал с представителем
  кластера. Цепочка A~B, B~C, A≁C не склеивается.
- `Transitive` — union-find, полнота выше, но одна плохая пара может слить две группы.

`keeper_policy` решает, какой файл отчёт рекомендует оставить: `HighestResolution`,
`LargestFile`, `OldestModified`, `NewestModified`, `ShortestPath`. При равенстве критерия
разрешение идёт к следующему, последним — кратчайший путь, ради детерминированного
результата. `reclaimable_bytes` считает, сколько освободится, если оставить только keeper.

**Библиотека ничего не удаляет и не изменяет на диске.** Она возвращает отчёт.

## 8. Кеш подписей

SQLite, выключен по умолчанию: скан не пишет ничего за пределами сканируемого дерева,
пока его об этом не попросят. Файл — `ghidraengine-cache.db` в первом корне скана, либо
`cache.path`. В пользовательские каталоги не пишется никогда.

Ключ строки — путь, размер, mtime и хеш тех настроек, которые меняют саму подпись
(`detect_exact`, `detect_similar`, `dihedral_invariant`, `min_dimension`, `frame_samples`,
`edge_skip_fraction`, `min_frame_variance`). Скан с другими настройками получает промах и
пересчитывает, а не сравнивает хеши, отвечающие на другой вопрос. Схема версионируется:
при несовпадении версии таблица подписей сбрасывается. Записи старше
`prune_after_days` удаляются при завершении скана.

## 9. Параллелизм и I/O

CPU-пул — `cpu_threads` потоков (0 = по `hardware_concurrency()`). Число одновременных
чтений ограничено отдельно: на флеше параллельные чтения — большой выигрыш, на вращающемся
диске они превращают последовательный поток в шторм seek'ов. При `io_threads = 0` тип
носителя определяется по первому корню скана (2 потока для HDD). Поток отпускает
I/O-разрешение сразу после чтения, до декодирования, — декод не занимает квоту диска.

## 10. SIMD

Ядра DCT живут в отдельных единицах трансляции со своими ISA-флагами, нужное выбирается в
рантайме через cpuid: AVX2+FMA → SSE2 → скаляр, NEON на AArch64. Для AVX2 проверяется не
только поддержка процессором, но и включённое состояние AVX в ОС (`xgetbv`). Тесты
проверяют, что все ядра дают **идентичный** хеш — иначе кеш, снятый на одной машине, был бы
несовместим с другой. Текущий бэкенд доступен через `active_simd_backend()`.

## 11. Модель ошибок

Ошибка отдельного файла (нет доступа, битый заголовок, неподдерживаемый кодек) попадает в
`Report::errors` и в колбэк `on_error`, но не роняет скан. `Result<Report>` возвращает
ошибку, только если скан не смог начаться: некорректная конфигурация, недоступные корни.
Отмена через `std::stop_token` даёт частичный отчёт с `cancelled = true`.
